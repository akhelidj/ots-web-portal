# T0.3 Authentication Foundation

## Overview
Implemented a secure authentication system using:
- **Local Strategy**: Email + Password (bcrypt hashed).
- **Access Token**: Short-lived JWT (stateless).
- **Refresh Token**: Long-lived, database-backed, revocable, hashed.
- **Security**: Default-deny posture using Global Guard and `@Public()` decorator.

## Schema Changes
### User
- Added `passwordHash String` (Required).
- Added relation `refreshTokens RefreshToken[]`.

### RefreshToken
- New model storing token hashes, expiry, and revocation status.
- Linked to `User`.

## API Endpoints
### Public
- `GET /health`: Health check.
- `POST /auth/login`: Authenticate and receive tokens.
- `POST /auth/refresh`: Rotate refresh token and get new access token.
- `POST /auth/logout`: Revoke refresh token.

### Protected
- `GET /auth/me`: user profile (requires Bearer token).
- All other application endpoints are protected by default.

## Environment Variables
- `JWT_ACCESS_SECRET`: Secret for signing access tokens.
- `JWT_ACCESS_TTL_SECONDS`: Access token lifetime (default: 900s).
- `REFRESH_TOKEN_TTL_DAYS`: Refresh token lifetime (default: 7d).

## Local Usage
1. **Provision**: `npm run db:provision` (Creates default tenants/users).
2. **Verify**: `npx -y tsx api/scripts/verify-auth.js` runs a full login/protected/logout flow.

## Verification
Automated script `verify-auth.js` confirms:
1. Login with valid credentials returns tokens.
2. Accessing protected route with token succeeds.
3. Accessing protected route without token fails (401).
