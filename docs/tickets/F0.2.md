# F0.2: Inspection Report Portal Integration

## Objective

Integrate the Inspection Report engine into the UI Portal with offline functionality, atomic sync outbox handling, and robust database architecture updates to support optimistic concurrency.

## Changes Made

1. **API Schema & Migrations**:
   - Added `version` field directly to `InspectionReport` and `SerialNumber` Prisma models to support optimistic concurrency control.
   - Generated corresponding database migrations.
2. **Backend API Surface Completion**:
   - Implemented standard CRUD and Transition endpoints for `InspectionReport` with tenant isolation.
   - Implemented `POST` and `PATCH` endpoints for `SerialNumber`.
   - Guaranteed consistent `409` conflict responses for version mismatches and integrated `AuditLog`.
3. **Portal IndexedDB Setup**:
   - Bumped `DbService` DB_VERSION to 4.
   - Created `inspection_reports` and `serial_numbers` object stores with indexes for `status`, `customerId`, and `syncState`.
4. **Portal Offline Repositories**:
   - Built robust `InspectionReportLocalRepo` and `SerialNumberLocalRepo` to map standard RxJS observability across the IndexedDB stores.
   - Included specialized methods like `remapId()` and `remapReportId()` to handle server-generated ID swapping.
5. **Sync Dispatcher & Orchestrator**:
   - Expanded the Outbox `SyncDispatcherService` to process `IR_CREATE`, `IR_UPDATE`, `IR_TRANSITION`, `SN_ADD`, and `SN_UPDATE` operations.
   - Integrated offline-to-online atomic UUID remapping.
   - Hooked up `InspectionReportsService` into the master `SyncOrchestratorService` hydration loop to seamlessly fetch and cache existing reports when online.
6. **Portal UI Screens**:
   - Built list, create, and detail offline-first components under `/inspector/reports/`.
   - Used optimistic updates and UI sync state indicators mapped over LocalDB streams. No components call `HttpClient` directly anymore.

## Manual Verification Guidelines

To manually verify the feature:

1. Ensure both API and Portal are running (`nx serve api`, `nx serve portal`).
2. Login as an Inspector (e.g., `inspector@example.com`).
3. Go Offline using Chrome DevTools.
4. Navigate to `/inspector/reports/create` and create a generic report. Ensure it appears in the list with a yellow "PENDING" tag.
5. Navigate into the detail view and Add Serial Numbers. Observe they enqueue successfully into PENDING.
6. Go back Online. Wait 2-5 seconds for the `SyncOrchestrator` to fire the ping queue.
7. Observe that the "PENDING" items immediately change to "SYNCED" and have their temp-IDs naturally remapped across the local store and Outbox dependencies.
8. Conflict Check: Go offline, edit a report via API directly using a different REST client, then edit locally. Go online, observe the Sync Dispatcher rejects the push with HTTP 409 Conflict, and flags the item in the UI with a distinct CONFLICT red marker.
