# Ticket F0.1.7: Tenant Isolation & Online Revalidation

This ticket hardened the tenant isolation of the system on both the backend and frontend to prevent any cross-tenant data caching or leaks. In addition, an offline-first but online-convergent sync orchestrator was developed.

## Architectural Notes

### Backend isolation
The backend relies on the `req.user.tenantId` extracted from the JWT.
Every list query and entity lookup incorporates `tenantId` (e.g., `customers.controller` and `users.controller`).

### Frontend DB Partitioning
IndexedDB is partitioned per tenant via `DbService` by prefixing the database name (e.g. `ots_{tenantId}`). 
The database is opened upon successful login and explicitly closed upon logout without wiping the local data. This prevents offline leaks between tenants while preserving their offline capabilities.

### Stale-While-Revalidate and Sync Orchestration
The UI reads directly from the Local Repository (IndexedDB) for immediate rendering.
A new `SyncOrchestratorService` triggers an automatic synchronization sequence whenever the app enters the `[isOnline = true, isAuthenticated = true]` state.
The orchestrator:
1. Flushes any pending OUTBOX mutations to the server.
2. Pours all fresh state from the server down to the local IndexedDB to ensure consistency (`pullAllAndCache`).
3. Emits `syncStatus$` and `lastSyncedAt$` which the Shell Component displays in real time.

## Manual Verification Script

1. **Verify offline tenant partitioning**:
   - Login as `admin@ots.com`. Inspect the application state (Users, Customers). Check Application Tab > IndexedDB. You should see `ots_ots-tenant-uuid`.
   - Logout.
   - Login as `admin@acme.com`. 
   - Observe that you only see ACME data. Checking IndexedDB will reveal a separate database `ots_acme-tenant-uuid`.
   - *Pass Criteria*: No Data from `ots.com` is visible when logged in to `acme.com`.

2. **Verify Sync Orchestrator UI Status**:
   - Disconnect network using browser DevTools.
   - The status bar should immediately say `Status: Offline`.
   - Reconnect network.
   - The status should briefly show `Status: Syncing...` and then transition to `Status: Up to date` with an updated `Last synced at` timestamp.
   - *Pass Criteria*: Sync status indicators accurately follow network and session transitions.

3. **Verify Stale-While-Revalidate**:
   - Go to `/admin/customers`.
   - Notice the data loads instantly. Look at the Network tab: a backend fetch for `/customers` happens seamlessly in the background.
   - *Pass Criteria*: Fast initial render with a stealthy background validation log.
