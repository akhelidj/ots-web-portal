# Ticket F0.2.1: Inspection Report Creation MVP (Offline-First)

## Objective

Enable authenticated internal users (Admin/Receiver) to view a list of Inspection Reports and create new ones offline-first. This unlocks the subsequent chains for Serial Numbers and workflow transitions.

## Schema Changes

N/A - Existing `InspectionReport` schema already contained all necessary locked terminology fields (`id`, `tenantId`, `customerId`, `poNumber`, `status`, `templateKey`, `templateVersion`, `templateHash`, `version`).

## API Endpoints

- **`GET /inspection-reports`**: Returns a list of all reports for the tenant.
- **`POST /inspection-reports`**: Creates an inspection report.
  - **Body Strictness:** Only accepts `customerId` and `poNumber`.
  - **Server-Side Resolution**: Automatically binds the `status` to `DRAFT`.
  - **Template Binding**: Resolves the `TEMPLATE` model for the active version of `DRILL_PIPE_REPORT` and binds the exact version integer and hash code onto the inspection report row permanently. Returns `400 Bad Request` if no such template is active.
  - **Validation**: Confirms the `customerId` lives in the same `tenantId`, returning `404 Not Found` to prevent data leakage.
- **`PATCH /inspection-reports/:id`**: Modifies the safe header properties (like `poNumber`). Enforces strict version optimistic concurrency (returning `409 Conflict` on mismatches).

### Auditing

- Creation invokes the exact, unchanged global tracking `AuditLog` format without demanding a manual `reason` rationale.

## Frontend Offline Architecture

### Repository & UI

- IndexedDB handles `InspectionReport` local data representations.
- The frontend consumes data completely independent of the network, via `listAll()` against the local IndexedDB.
- The UI creation interface works offline using locally populated lists of `Customer` options.

### Outbox Implementation

- Dispatching an `IR_CREATE` operation creates an instantaneous representation within the offline IndexedDB while the outbox orchestrator prepares the network queue.
- On online completion, the UUID client-side temporal constraint is strictly swapped for the authoritative server-side generated UUID sequence (Atomic ID Remapping).
- Dispatching an `IR_UPDATE` performs modifications and increments locally, while pending a transaction that requires sequential `409 Conflict` safety checking.

## Manual Verification Steps

1. Log into the Angular portal and navigate to the Inspection Reports list in the portal (via main navigation).
2. Turn off the network connection (e.g., via browser developer tools offline or network throttling mode).
3. Click "Create Report" and create a new report choosing a Customer from the dropdown and entering a `poNumber`.
4. Verify the report appears instantly in the list with a `PENDING` sync status and is permanently saved in the application IndexedDB persistence layer.
5. Restore the network connection to normal operating behavior.
6. Verify the Outbox dispatcher triggers the creation HTTP POST automatically, and the UI status turns `SYNCED`.
7. Refresh the page to verify the API returns the correctly created report alongside the accurate mapping bindings determined by the Server resolution logic.
