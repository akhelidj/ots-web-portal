# F0.2.4 — Inspection Data Entry MVP (Offline-First)

## Implementation Notes

- **Schema**: Reused the existing `inspectionData` column (`Json?`) in the Prisma `SerialNumber` schema without writing new migrations. The payload mapping to/from `inspectionJson` is handled entirely via NestJS service and controller logic.
- **Backend**:
  - `PATCH /api/serial-numbers/:id` supports atomic optimistic concurrency via `version` match using `update`.
  - Added lockdown block if the `InspectionReport` is `APPROVED` or `CLOSED`.
  - Emits tracking audit log events upon changes.
  - Returns `inspectionJson` properly mapped on report endpoints.
- **Offline Core**:
  - Implemented `SN_UPDATE_INSPECTION` logic within the Angular sync dispatcher natively handling 400 (reverts local to ERROR) and 409 (CONFLICT) statuses.
- **UI**:
  - Exposed Drill Pipe v1 static schematic fields in a side-panel form within the serial numbers view.
  - Automatically disables when the parent report status is locked.

## Acceptance Criteria Met

1. Inspector can open a Serial Number and edit inspection fields.
2. Data persists offline and survives refresh.
3. Sync updates backend and increments version.
4. 409 conflicts handled.
5. Inspection data becomes read-only when status = APPROVED or CLOSED.
6. No route names in docs.
7. No noise files created.
8. Docs added (`docs/api/serial-number-inspection.md`, `docs/tickets/F0.2.4.md`).
